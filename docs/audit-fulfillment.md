# 采购与销售订单履行核对

逆向资料中，销售和采购分别有独立的预订、转单和单据列表。前端调用 `calculateUnitQty` 时传入本次数量、单位索引和订单明细 ID。销售列表还展示关联订单号和发货状态。可确认参考系统保留了订单明细与业务单据的关系。参考后端如何锁定余量、计价与写库存，现有材料无法直接确认。依据见 `zhjspace/docs/10-后端逻辑说明（前端反推）.md` 的销售、采购单据部分及 `audit-reference-routes.md` 的转单路由。

| 检查项 | 禾序实现与验证 |
|---|---|
| 一单分批 | 订单可按原明细选择本次数量。同商品的两条明细分别追踪，即使价格相异。报价仍一次转单。 |
| 履行数量 | 每行显示订购、已过账、草稿占用及可转数量。多个草稿不能合计超出订单。取消草稿释放占用。 |
| 关联批次 | 原订单详情显示批次草稿编号、日期、审核状态和正式单号，包括已取消批次。 |
| 过账一致性 | 草稿生成不改库存。采购入库或销售出库与审核状态同事务提交。库存不足时草稿及其占用保留，重复审核拒绝。 |
| 订单约束 | 批次沿用原订单仓库、往来方、商品、单位和单价。保留订单指定批次。草稿默认使用不早于订单的当前业务日期，允许在约束内改日期。 |
| 权限 | 工作流按采购和销售权限限制可见及可编辑范围。审核和转单另需审核权限。 |
| 历史账套 | 旧转单未保存原订单行标识，显示历史整单转单并保留关联。不会猜测剩余数量。若是旧草稿，可取消后重新分批。 |

测试覆盖两行订单多批到货、草稿取消、跨批超量、单位约束、库存不足回滚和历史单据兼容。Node、Vue 类型检查通过，全量回归 46 个文件、369 项通过。最终版本的工作流与演示账套定向回归 10 项通过。桌面冒烟在临时账套从 6 件订单中生成 2 件草稿，审核后再转余下 4 件，最终订单标为已履行，库存由 7 件增加到 13 件。

退货是否重开原订单、分批订金抵扣、红冲回退履行进度、订单跨仓履行及配送字段仍需单独核对。普通采购和销售的直接过账入口也需与审核权限统一验收。
