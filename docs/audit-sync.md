# 云盘同步与恢复核对

以原始设计 §5.3、P4 T1/T2/T7 和《离线进销存详细功能设计》的数据保障要求为参照。目录副本与 WebDAV 传输完整、可校验的 SQLite 快照。目录模式只能确认目标路径文件，云盘客户端负责后续上传。

| 场景 | 本轮行为和验证 |
|---|---|
| 两个目标可用性不同 | 目录副本与 WebDAV 分别检查，显示快照版本、时间和错误。WebDAV 失败时可明确选择目录副本预览。整体上传仍会在目标状态未知时停止，避免覆盖未核对的版本。 |
| 同一共享目录被并发写入 | 两个写入方观察到同一个起点时，仅一个提交成功。替换前取得独占写入标记，在标记保护下再校验实际文件，最终以重命名替换。独立云盘客户端之间仍需单主机写入，客户端复制可能延迟。 |
| WebDAV 被另一个客户端抢先更新 | 新文件使用 `If-None-Match: *`。覆盖用读取时获得的强 `ETag` 配合 `If-Match`。收到 412 时停止并报告冲突。目标已有快照但不提供强 `ETag` 时停止覆盖。模拟 HTTP 用例验证这两类条件请求。 |
| 同序号却不同内容 | 远端相同序号的多个不同快照停止自动选择。当前快照与已知本地基准同序号却不同校验值时停止覆盖。 |
| 有本地变更时恢复 | 恢复前并排展示本地与快照商品、往来和过账单据数量及最近业务日期。系统根据上次快照的业务指纹识别本地变化。历史未建立基准的非空账套也需显式确认。 |
| 确认前本地再次变化 | 预览令牌有效期十分钟。提交时再次核对待恢复文件校验值和本地业务指纹。变动后必须重新预览。通过校验后才生成恢复前副本、暂存并重启应用。 |

上架前仍需实测目标云盘或 WebDAV 服务的条件请求、断线与大账套行为。版本历史浏览与保留策略、分目标重试记录、可选快照加密，以及恢复为独立账套尚未实现。当前快照仍采用整账套恢复，设计边界为单主机写入。

Node 与 Vue 类型检查通过。全量回归 46 个文件、366 项通过，补充指定副本预览后再跑了同步和备份的 19 项测试。桌面冒烟在临时账套上传目录快照后修改本地设置，验证界面提示本地变更、未确认时禁止恢复，并取消预览。
